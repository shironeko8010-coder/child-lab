# 設計書：べんきょう「ずかん」のグレードアップ

前の設計書：`docs/superpowers/specs/2026-11-12-benkyo-zukan-design.md`（画面の流れ・カード・わたしのずかん は そのまま。この設計書は 変えるところだけを書く）

## 1. 目的
- ずかんを、もっと広く（テーマを増やす）、もっと多く（ページを増やす）、もっと深く（説明と問題を増やす）する。やまとさんの希望「ずかんのグレードアップ」。
- 小2の子が、読んで知る楽しさと、よく読めば答えられる問題で、読む力・考える力をのばす。

## 2. 決めたこと（やまとさんと決めた）
| 項目 | 今 | グレードアップ後 |
|---|---|---|
| テーマ | 9 | 12（新しく「たべもの」「きせつと ぎょうじ」「ディズニーリゾート」） |
| 1テーマのページ | 12 | 16 |
| ページの合計 | 108 | 192（新しいページ 84） |
| 1ページの説明 | 2文くらい | 説明（今の文）＋ まめちしき（1〜2文）＝ 3〜4文 |
| 1ページの問題 | 2問 | 3問（3問目は「よく読むと わかる」少し難しい問題） |

- 3回に分けて作る（7章）。各回のはじめに 確認ページを作り、やまとさんに中身を見てもらってから 声を作る。
- 長くなった説明は、スマホでは2まいに分けて見せる（5章、案A）。
- ページのデータは、テーマのまとまりごとにファイルを分ける（8章、案A）。

### 考えた作り方（Approaches）
| 点 | 案 | 決め |
|---|---|---|
| スマホでの長い説明 | A 2まいに分ける（説明 → つぎへ → まめちしき） | **採用**（字を小さくしない・スクロールなし の決まりを守れる） |
| | B 字を小さくして入れる | 不採用（字18px以上の決まりを守れないことがある） |
| データの置き方 | A テーマのまとまりごとにファイルを分ける | **採用**（1ファイルが大きくなりすぎない。3回に分けて作るのに合う） |
| | B 1ファイルのまま | 不採用（とても大きなファイルになる） |

## 3. ページの中身
- **説明**（`text`）：今の文（2文くらい）。新しいページも同じ長さ。
- **まめちしき**（`mame`）：1〜2文。説明とは べつの、「へえ！」と思う事実。
- **問題**（`qs`、3つ）：それぞれ「問い・答え1つ・まちがい3つ」。
  - 1・2問目：説明を読めば答えられる問題（今と同じ）。
  - 3問目：まめちしきを読めば答えられる問題（「よく読むと わかる」）。
- 今の決まりは そのまま：答えのことばは説明かまめちしきの中に出てくる／正しいとも言える選択肢を まちがいに入れない／問いは「？」で終わる文／読み上げの部品は 助詞の「は」で始めない。
- 漢字：べんきょうの決まり（1年生の漢字はそのまま、2年生の漢字は `{漢字|よみ}`、3年生以上は ひらがな）。
- 絵：絵文字（Unicode 12 以前、ZWJ を使わない）。ぴったりの絵文字がないときだけ、今と同じく SVG（`zukan-art.js`）を足す。同じテーマの中で、同じ絵を2回使わない。

## 4. 新しいテーマ
| テーマ（id） | 名前（画面） | 中身の例（16ページ） |
|---|---|---|
| たべもの（tabemono） | たべもの | お米・パン・牛にゅう・たまご・みそ・とうふ・しょうゆ・のり など。「どこから来るか」「何から できるか」 |
| きせつと ぎょうじ（kisetsu） | きせつと ぎょうじ | お正月・せつぶん・ひなまつり・こどもの日・七夕・お月見・クリスマス・大みそか など |
| ディズニーリゾート（disney） | ディズニーリゾート | 東京ディズニーランド 8ページ・東京ディズニーシー 8ページ。場所・できた年・シンデレラ城・プロメテウス火山・舞浜駅とモノレール・うめ立ての土地・パレードや花火のしくみ など |

### ディズニーリゾートの決まり
- キャラクターの絵・ロゴは使わない（著作物・商標のため）。絵は ふつうの絵文字（🏰 🌋 🚝 🎆 🚢 など）だけ。
- **アトラクションのページ・問題を多めにする**（やまとさんの希望）。16ページのうち 8ページ以上をアトラクション（ランド・シー 半分ずつくらい）にし、のこりを 場所・建物・しくみ にする。アトラクションのページの問題も、そのアトラクションの中身（どんな のりものか、どこにあるか、何を するか など）にする。
- キャラクターの名前は、建物・場所・アトラクションの名前に入っているときだけ使う（例「シンデレラ城」「プーさんのハニーハント」）。ページの中身は、のりもの・建物・しくみ の事実にし、キャラクターの おはなしを主役にしない。
- アトラクションは 終わったり新しくなったりするので、長く続いていて、作った時点で あると考えられるものを選ぶ（工事やリニューアルで休んでいると分かっているものは さける）。それでも変わりうるので、確認ページで必ず見てもらう。
- 宣伝の文にしない（「たのしい！」「行こう！」のような さそう文は書かない）。事実だけ。
- 確認ページで、やまとさんに 事実が合っているかを必ず見てもらう（私の知識が古い・まちがっている可能性があるため）。

## 5. 画面（長い説明の見せ方）
- タブレット（スマホの大きさでない画面）：ページの画面に、説明とまめちしきを1まいで出す（まめちしきは「まめちしき」の見出しをつけて、説明の下に）。
- スマホの大きさ（よこ向きで高さ520px以下、たて向きで幅520px以下）：いつも2まいに分ける。1まい目＝絵・名前・説明＋「つぎへ」。2まい目＝「まめちしき」の見出し＋まめちしき＋「{読|よ}めた！」。
- 読み上げ：1まい目で説明、2まい目でまめちしきを読む（タブレットは 説明のあとに続けて まめちしき）。スピーカーのボタンは、いま見えている文を読む。
- 問題の画面は今と同じ（1問ずつ）。3問になるので、1ページのあいだの進み具合は 3つの点で見せる。
- スクロールなし：スマホ 667×375・740×360・812×375・375×667・360×740・390×844、タブレット 1280×800・1024×600。字は主な字18px以上・補足16px以上、ボタン56px以上（高さ340px以下は48px）。いちばん長い説明・まめちしきのページで確かめる。
- テーマ画面：12テーマ。今の並べ方（スマホよこ3列×3段、たて3列）では入らないので、スマホよこ 4列×3段、たて 3列×4段 にする（カードは今の大きさの決まりのまま）。

## 6. カード・記録
- 今と同じ：1ページにつき記録1件（`area: 'zukan'`、`itemId` はページの id）。3問とも1回目で正解なら きらきら（`correct: true`）、そうでなければ カード。
- 今までの記録（108ページ）は そのまま使える（ページの id を変えない）。
- 1回分は 今と同じ 3ページ（3ページ × 3問 ＝ 9問）。

## 9. テスト（今のテストを広げる）
- ページの数：回ごとの数。id が重ならない。今の108ページの id が すべて残っている。
- どのページも：絵・説明・まめちしき・問題3つ（答え1つ＋まちがい3つ、重ならない）。
- 3問目の答えは まめちしきの中に出てくる。1・2問目の答えは 説明か まめちしきの中に出てくる。
- 漢字の決まり・「は」で始めない・正しいとも言える選択肢を入れない・問いは「？」で終わる（今のテストを まめちしきと3問目にも使う）。
- 同じテーマの中で 絵が重ならない。
- ディズニーリゾート：キャラクターの名前だけの絵文字やページがない（名前に「城」などの建物・場所のことばが入るものは よい）。
- 画面：まめちしきがある／スマホの大きさでは2まい（1まい目→つぎへ→2まい目→読めた！→問題）／3問で1ページおわり、記録1件。
- 読み上げ文がすべて音声ファイルにある。PRECACHE と公開に新しいファイルが入る。
- 大きさ：8つの画面の大きさで、テーマ画面・ページ（いちばん長い説明・まめちしき）・問題 に スクロールが出ない。
- 中身の正しさ・2年生に合うかは、確認ページで やまとさんに見てもらう。

## 10. 未確認・制約
- 図鑑の事実は 私（Claude）の知識で書く。まちがい・古い情報がありうるので、確認ページで見てもらう。特にディズニーリゾート（変わりやすい）と、数（高さ・年・数量）。
- 声は、増える文（まめちしき 192・3問目 192・新しいページの説明と問題）の分を ずんだもんで作る（合わせて 千文くらい。作るのに 20〜30分くらい）。
- ディズニーリゾートは、家庭で使うための教材として事実だけを書く。絵・ロゴは使わない。

## 11. 作る人の判断（読み手のチェックで出た点）〔作る人の判断〕
1. 新しい3テーマは、3回目に THEMES に足す（1・2回目は9テーマのまま。ページの無いテーマのカードは出さない）。テーマ画面の4列×3段（たて3列×4段）も3回目に作る。
2. テストの「ページの数」は、テストの中の1つの決まり（例 `EXPECT = { themes: 9, perTheme: 12 }`）を回ごとに書きかえる。「今の108ページの id がすべて残っている」は、どの回でも確かめる。
3. 声は 今と同じ道具（`tools/voice-lines.html` → `lines.tsv` → `perl tools/voice/make.pl`）で、やまとさんのパソコンの VOICEVOX を使って作る（PowerShell は使わない）。VOICEVOX が止まっていたら起動をお願いする。声は確認ページで直したあとに作る。そのあいだ「すべて音声ファイルがある」テストは 新しい文の分だけ失敗する。
4. 声は文ごと（今と同じく。説明・まめちしき それぞれ 文に分かれて音声ファイルになる）。タブレットでは 説明のあとに続けて まめちしきを読む。「まめちしき」の見出しは読まない。スマホの2まいでは、そのまいの文だけを読む。
5. 3つの点は 何問目かだけを見せる（今の2問のときと同じ見せ方）。3問目に「よく読むと わかる」の印は つけない（中身だけ少し むずかしくする）。
6. テーマ画面がスマホの低い画面で入らないときは、カードを「絵と名前を横に並べる形」（今のスマホよこ と同じ）にし、それでも入らなければ 題の文（テーマを えらんでね）を画面に出さない（声では読む）。字・ボタンの大きさの決まりは下げない。スクロールはしない。
7. 新しいページの id は、今と同じく ローマ字か英語の短いことば（例 `onigiri`、`tanabata`、`shiro`）で、全ページで重ならない（テストで確かめる）。今の108ページの id は変えない。SVG の名前も同じ決まり。
