# 見切れ修正 第2弾（fix-layout2）報告

## 1. いちばん大事な発見：実機スクショは「修正前のCSS」で表示されていた

実機スクショ（12〜16.webp）を、修正前のコミット `3da7c1f` と比べた。

| 測った所 | 実機スクショ（画素 ÷ 2.17） | 修正前CSSを 921x414 で表示した値 | 修正後CSS（現行）を同じ大きさで表示した値 |
|---|---|---|---|
| 左上の家ボタン | 72px（上端 12px） | 72px（上端 12px） | 56px |
| 文字の丸（q-letter） | 120px（上端 88px） | 120px（上端 88px） | 約91px |
| 絵カード | 幅200px（上端 224px） | 幅200px（上端 224px） | 幅最大170px |
| なぞる画面の右の列 | 幅300px・ふきだし28px | 300px・28px | clamp(200px,32vw,280px) |
| ごほうびの星 | 約106〜120px | 120px | 14vh（約58px） |

- 縮尺を 2000/921 ≒ 2.17 とすると、すべての値が**修正前の app.css（3da7c1f）と一致**した。修正後の「スマホ横向き用ルール」は1つも効いていない。
- 実機の表示領域は、56px ボタンを前提にした逆算（714x321）ではなく、**約 921x414（ステータスバー等を除く）**と考えられる。
- 修正前CSSを 921x414 で開いたスクショは、実機スクショ13とほぼ同じ見た目になった。
- 原因として考えられること（確かめていない）：
  1. Service Worker（`sw.js`）が「キャッシュ優先」のため、端末に古い CSS が残っている。新しい sw.js が入っても、その時に開いていた画面は古いファイルのまま。もう一度開き直すまで新しいCSSにならない。ホーム画面に追加したアプリは、閉じきらないと開き直しにならないことがある。
  2. GitHub Pages への反映（Actions）が終わる前に確認した。
- **今回のCSS修正だけでは、この「古いファイルが出続ける」問題は直らない。** sw.js の取得方法を「ネットワーク優先（オフライン時だけキャッシュ）」や「キャッシュを返しつつ裏で更新」に変える案を検討してほしい（sw.js は今回の担当範囲外なので触っていない）。

## 2. 変えたこと

### app-chiiku/app.css
- スマホ横向き（`orientation: landscape` かつ `max-height: 520px`）：
  - `.app` を **高さ = 100dvh に固定**（`min-height` から `height` へ）。上の帯は `flex: 0 0 auto`、本体（home-body / trace-wrap / reward-body / rest-body / cards）は `min-height: 0` で残りの高さだけを受け取る。中身がはみ出しても、画面の下に押し出されない。
  - 親画面（`.scr-parent`）だけは `height: auto`（縦スクロール可）。
  - えらぶ画面：`.cards` を `flex: 1 1 0` にして「残りの高さ」いっぱいの段にし、カードは段の高さに合わせる（`height: 100%`、上限 `60vh`、下に影の分 10px）。高さが足りなくても、カードが画面の外に出ない。絵は `18vh` に少し大きくした。
- さらに低い横向き（`max-height: 340px`）：上の帯・アイコンボタンを **48px** に。なぞる画面のボタンは `clamp(48px, 16vh, 64px)`、「つぎへ」は `clamp(48px, 17vh, 64px)`。浮いた高さは、なぞり板に回る。

### shared/ui.css
- `max-height: 340px` の横向きだけ `--tap-min: 48px`（341〜520px は 56px のまま、タブレットは 64px のまま）。
- `html, body` に `-webkit-text-size-adjust: 100%; text-size-adjust: 100%`（スマホ横向きで、ブラウザが文字だけを大きくしてはみ出すのを防ぐ）。
- おとなゲート（横向きスマホ）：情報とキーを**必ず横に並べる**（`flex-wrap: nowrap`、`.g-info` を縮められるように）。568x320 では折り返して、キーが画面の下（bottom 501px）に出ていた。

### app-chiiku/game.js（なぞり板の大きさ計算だけ）
- 板の一辺は、これまでどおり「なぞる場所（trace-area）の幅と高さの小さい方 − 8px」。trace-area の高さは、上の帯を除いた残りの高さ（CSSで固定）なので、**板の一辺 = 使える高さ − 上の帯**になる。
- 追加：trace-area の下端が画面（`innerHeight`）より下に出ている場合は、`innerHeight − 上端 − 8px` を上限にする（dvh が使えない古いブラウザで、アドレスバーの分だけ高く計算される場合の保険）。
- 板の最小値を 200px → 160px に（とても低い画面で、板が下にはみ出さないように）。

### index.html の `<style>`
- 変更なし（現行のルールで全サイズ収まることを確認した）。

## 5. 確認していないこと・懸念
- **実機（Androidスマホ）では確認していない。** 上の 1. のとおり、実機には古いファイルが出ていた可能性が高い。実機で確認するときは、先に古いキャッシュを消す必要がある（例：Chrome の「サイトの設定」→ 該当サイトの「データを削除」、ホーム画面のアプリなら一度完全に閉じてから2回開き直す）。sw.js の CACHE_NAME の番号上げも必要。
- 確かめ方の例：横向きで、えらぶ画面の左上の家ボタンが「小さめ（帯の高さが画面の約1/6）」になっていれば新しいCSS。家ボタンが大きく（修正前と同じ）なら、まだ古いCSS。
- dvh が使えない古いブラウザ向けの game.js の保険（innerHeight で上限）は、実際の古いブラウザでは試していない。
- 文字の拡大（Android のユーザー補助の文字サイズ）が大きい設定だと、ふきだしの文字が増えて、なぞる画面の右の列が高くなる可能性がある（今回は標準の文字サイズで計測）。
- プロフィール作成画面は、キーボードが出た状態は計測していない（キーボードで画面の高さが減ると、入力欄の周りがスクロールになる）。
