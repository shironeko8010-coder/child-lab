# 設計書：ちいく「めいろ」と、ホームの2ページ化

## 1. 目的
- 5歳の子が、親なしで、指でひよこを引っぱって めいろを進む。字が読めなくても遊べる。
- 指先を思いどおりに動かす練習（なぞり書きの前の力）と、先を見て道を選ぶ力を育てる。
- 「簡単すぎない」こと（やまとさんの希望）。むずかしさは、めいろの大きさに加えて「ほし」「かぎと とびら」のルールで上げる。スマホでは道を太くする必要があり、めいろを大きくするのに限界があるため。
- 叱らない。迷ったら道を光らせて教える。

見本：`docs/maze-samples.html`（やまとさんが「このままでOK」と確認した形）。

## 2. 決めたこと（やまとさんと決めた）
| 項目 | 決めたこと |
|---|---|
| 動かし方 | ひよこを指で引っぱる（案A）。壁には入れない。指を離しても、その場所で止まって続きからできる |
| むずかしさ | めいろの大きさ＋ルール（ほし・かぎと とびら）。レベル1〜5（4章） |
| 作り方 | マス目のめいろを毎回自動で作る（案1）。ひよこはマスからマスへ、道がつながっている方向にだけ進む |
| ホーム | 2ページに分ける。1ページ6まい（7章） |

### 考えた作り方（Approaches）
| 案 | 中身 | 決め |
|---|---|---|
| 1 マス目＋自動で作る | 毎回ちがうめいろ。壁を通りぬけない。テストしやすい | **採用** |
| 2 自由に動かす | なめらかだが、壁のすき間で引っかかる・すり抜けるが起きやすい | 不採用 |
| 3 作っておいためいろ | むずかしさは調整しやすいが、すぐ覚えてしまう | 不採用 |

## 3. 遊び方（1回の流れ）
1. めいろが出る。ひよこ（左下）と ごはん（右上）。ひよこが「ごはんまで つれていってね」と言う（レベルごとの文は8章）。
2. 子どもが ひよこを引っぱる。指の場所へ向かって、道がつながっていれば1マスずつ進む。
3. 通った道に、あしあと（点線）が残る。もどると あしあとも消える。
4. ほし・かぎを通ると拾う（効果音＋短い声）。
5. ごはんに着いたらゴール（正解の効果音＋「ごはん だ！ やったね」）。
6. めいろ3つで1回分。3つ終わったら、ごほうび画面（今の遊びと同じ）。

### 指の動き
- ひよこのマス、または そのとなりのマスを さわったら、引っぱり始める。
- 引っぱっている間、指のあるマスへ向かって、たて・よこの 指に近い方向から先に進めるか試す。進めなければ もう一方を試す。どちらも壁なら止まる（指だけ先に行っても、ひよこは壁の手前で待つ）。1回の指の動きで、最大4マスまで進む。
- ひよこから離れた場所を さわったときは動かない。3回続いたら「ひよこを さわって うごかしてね」と言い、ひよこを少しはねさせる。
- ひよこはマスの間を短い動き（約0.12秒）で歩く。カクカクさせない。

## 4. レベル
| レベル | めいろの大きさ（よこ×たて） | ルール | 道のつながり（まよいにくさ） |
|---|---|---|---|
| 1 | スマホよこ 5×3／たて 4×5／タブレット 6×4 | ごはんへ行く | 多め（壁を25%こわす） |
| 2 | スマホよこ 7×4／たて 4×6／タブレット 8×5 | ごはんへ行く | 少なめ（5%）＝行き止まりが多い |
| 3 | スマホよこ 10×5／たて 6×8／タブレット 12×8 | ほしを3つ拾うまで、ごはんに ふたが しまっている | 5% |
| 4 | 3と同じ | かぎを拾うと、ごはんの前の とびらが開く | 5% |
| 5 | 3と同じ | ほし3つ ＋ かぎと とびら | 3% |

- 画面の向き・大きさの決め方：画面の向きがよこなら「スマホよこ」、たてなら「スマホたて」。どちらでも、短い辺が 700px 以上ならタブレットの大きさ。タブレットのたて向きは、表の よこ×たて を入れかえる（例 12×8 → 8×12）。
- 表の大きさは「いちばん大きいとき」。`dims(level, kind)` は表のとおりの値を返し、実際の大きさは `fit(level, kind, availW, availH)` が決める（availW・availH は、めいろに使える幅と高さ。上の帯を除いた、見えている高さ）。マスの大きさ＝ min(availW ÷ よこ, availH ÷ たて)。それが 56px（とても低い横向き＝高さ340px以下は 48px）より小さいときは、マスが小さい方の向き（よこ／たて）のマス数を1つ減らして、もう一度計算する。どちらも 3 より小さくはしない。〔作る人の判断〕
- 確かめる画面の大きさ：スマホ 667×375・740×360・812×375・375×667・360×740・390×844、タブレット 1280×800・1024×600（これまでの確認と同じ8つ）。
- めいろの途中で画面の向きが変わったら、同じレベルで新しいめいろを作り直す（形が合わなくなるため）。1回分のめいろの数（3つのうち何個目か）は そのまま。拾った ほし・かぎ と「ヒントが出た」は、新しいめいろなので 消える。作り直しは記録しない。〔作る人の判断〕
- レベルの上がり下がりは、今の遊びと同じ `C.adaptive.nextLevel`（最高5）。めいろ1つを1問として数える。
- 「せいかい」＝ヒント（6章）が出る前にゴールしたとき。ヒントが出たら、ゴールしても「まちがい」として記録する（叱る声や表示はない）。
- 記録は `area: 'meiro'`、`itemId` は `'lv' + レベル`（例 `'lv3'`）、`level` はレベル。

## 5. めいろの作り方
- 穴ほり法（スタートから、まだ行っていないとなりのマスへ ランダムに道をほり、行き止まりで1つもどる）で、すべてのマスがつながっためいろを作る。そのあと、レベルの割合で、となりどうしの壁をランダムにこわして道をつなげる。
- スタート：左下のマス。ゴール：右上のマス。
- ゴールは行き止まりにする（入り口は1つ。スタートからゴールまでの道の、ゴールの1つ手前のマスとだけつなぐ）。通りぬけられると、ふたが しまっている間に その先へ行けなくなるため。
- とびら（レベル4・5）：ゴールの入り口のマス（マスそのものに とびらの絵を置く。壁ではない）。かぎを持つまで、そのマスに入れない。とびらのマスの先に ほしがある場合もある（かぎを拾えば行ける）。
- かぎ：とびらを通らずに行けるマスのうち、スタートからゴールへの道から外れていて、スタートから いちばん遠いマス。そういうマスがなければ、とびらを通らずに行ける いちばん遠いマス。
- ほし（3つ）：スタート・ゴール・かぎ・とびら以外のマスを、スタートから遠い順に並べ、だいたい同じ間をあけて3つ選ぶ（同じ所に かたまらない）。
- 必ずゴールまで行けること：作ったあとに確かめ、行けなければ作り直す（ふつうは起きない）。
- 乱数は `rng`（0以上1未満を返す関数）を渡せるようにして、テストで同じめいろを作れるようにする。

## 6. ヒント
- 6秒間ひよこが動かなかったら、「いま行くべき所」までの道を黄色く光らせる。動いたら消える。
- いま行くべき所：まだ拾っていない ほしのうち、いまの状態で行けるもの（かぎが なければ とびらを通らない）があれば、いちばん近い ほし。なければ、かぎを持っていなければ かぎ。それもなければ ごはん（このとき ほしは すべて拾っているので、ふたは あいている）。かぎは いつも とびらを通らずに行けるので、この順で必ず ゴールまで行ける。
- ヒントは何度でも出る。ヒントが出たら、そのめいろは「まちがい」として記録する（4章）。
- 声：はじめてヒントが出たとき「ひかっている みちを すすんでね」と言う。

## 7. ホームの2ページ化
- 1ページ6まい。1ページ目：ひらがな・かず・とけい・いろ・かたち・まちがいさがし・おかいもの。2ページ目：しりとり・どうとく・めいろ。
- 並べ方：たて向き・よこ向きとも、3まい×2だん（2ページ目は 3まい×1だん）。カードの大きさは今の決まり（字18px以上・ボタン56px以上）。
- ページの切りかえ：画面の左右に大きな「◀」「▶」ボタン（56px以上。最初のページでは◀、最後のページでは▶を うすくして押せなくする）。カードの下に「●○」でいまのページを出す。指で横にさっと動かしても（40px以上の横の動き）めくれる。
- ページを切りかえたときは、効果音（tap）を鳴らす。
- 遊びから「おうち」でホームにもどったときは、その遊びがあるページを出す（めいろから もどったら2ページ目）。アプリを開き直したときは1ページ目。いまのページは画面の中だけで覚え、保存はしない。〔作る人の判断〕
- 横にさっと動かしてめくる動きと、めいろの指の動きは、どちらも pointer イベント（pointerdown／pointermove／pointerup）で読む。別の画面なので ぶつからない。めいろの板は `touch-action: none` にして、引っぱっている間に 画面が動かないようにする。〔作る人の判断〕
- 「めいろ」のカード：新しい色、絵は「めいろの中の ひよこ」のSVG。

| はじめ（レベル3） | 「ほしを 3つ ひろってから、ごはんへ いこう」 |
| はじめ（レベル4） | 「かぎで とびらを あけて、ごはんへ いこう」 |
| はじめ（レベル5） | 「ほし 3つと かぎを ひろって、ごはんへ いこう」 |
| ほしを拾った | 「ほし ゲット！」 |
| ほしが そろった | 「ごはんの ふたが あいたよ！」 |
| ほしが そろったが、かぎがまだ | 「つぎは かぎを さがそう」 |
| かぎを拾った | 「とびらが あいたよ！」 |

- `tools/voice-lines.js` は、ソースの `speak('…')` を集めるので、上の文は `speak('…')` の形で書く。そのあと `tools/voice-lines.html` で一覧を作り、`make.pl --preview` で読みを確かめてから、`make.pl` で作る。今ある文の読みは変えない（一覧の差分で確かめる）。
- 部品は「は」で始めない（VOICEVOX が「ワ」と読むため）。

## 9. 画面
- 上の帯：おうちボタン（左）・ふきだし・集めるものの一覧（⭐⭐⭐🔑。拾うと色がつく）・音楽ボタン（右）。今の遊びと同じ部品（`C.chiikuUi.topBar`）を使う。
- スマホたて向きでは、ふきだしを上の帯の下の行に出す（見本と同じ。横に並べると字が切れるため）。
- めいろ：うすいクリーム色の地面に、緑の生けがき（壁）。絵はSVG（ひよこ・ごはん・ふた・ほし・かぎ・とびら）。外の画像は使わない。
- スクロールなし。スマホたて・よこ、タブレットで、めいろ全体が画面に入る。
- ごほうび画面・お休み画面は、今の遊びと同じもの（`C.chiikuUi`）を使う。

`C.meiro` が外に出すもの（テスト用）：
- `AREA`（'meiro'）、`MAX_LEVEL`（5）、`ROUND`（3）、`LEVELS`（4章の表）
- `dims(level, kind)` → `{ w, h }`（kind は 'land' | 'port' | 'tab' | 'tabPort'。表のとおり。'tabPort' は 'tab' の入れかえ）
- `fit(level, kind, availW, availH, minCell)` → `{ w, h, cell }`（4章の減らし方）
- `make(level, w, h, rng)` → `{ w, h, cells, start, goal, stars, key, door }`（cells[y][x] は `{ n, e, s, w }` で 1 なら道がある。位置は `'x,y'` の文字列）
- `canMove(maze, from, dir, state)` → 進めるなら行き先、だめなら null（state は `{ hasKey, starsLeft }`。とびら・ふたも見る）
- `path(maze, from, to, state)` → 道のマスの配列（行けなければ null）
- `nextTarget(maze, at, state)` → 6章の「いま行くべき所」
- `speakStart(level)` → はじめの文
- `progressFromLogs(logs)` → `{ level, recent }`
- `start(profileId)`

## 11. テスト
- `make`：どのレベル・大きさでも（乱数を変えて各50回）、すべてのマスがつながっている。ゴールは入り口が1つ。スタートからゴールまで行ける。
- ほし：レベル3・5で3つ、1・2・4で0。スタート・ゴール・かぎ・とびらと重ならず、3つともちがう場所。
- かぎ・とびら：レベル4・5だけ。とびらはゴールの入り口。かぎは とびらを通らずに行ける。
- `canMove`：壁の方向は null。かぎを持たずに とびらへは null、持てば進める。ほしが残っていると ごはんへは null。
- 解けるか：`nextTarget` と `path` をたどって、どのレベル・向きでも（乱数を変えて各50回）、ほし・かぎを拾って ごはんまで行ける（見本で確かめた方法と同じ）。
- `dims`：表のとおり。`fit`：8つの画面の大きさで、マスが 56px（高さ340px以下は48px）以上になり、よこ・たてとも3以上。
- `progressFromLogs`：今の遊びと同じく、直近5つで4つ「せいかい」ならレベルが上がる。
- ホーム：1ページ目に6まい、2ページ目に3まい（めいろがある）。▶で2ページ目、◀で1ページ目。最初のページで◀、最後のページで▶は押せない。
- 読み上げ文がすべて音声ファイルにある（今の「すべて音声ファイルがある」テストで確かめる）。
- PRECACHE と公開（pages.yml）に meiro.js が入る（今のテストで確かめる）。
- 大きさ：スマホ6サイズとタブレット2サイズで、めいろ画面・ホームの両ページにスクロールが出ない。マスは56px以上（とても低い横向きは48px以上）。
- 実機（スマホ・Androidタブレット）での指の動かしやすさ・読み上げは、やまとさんに確かめてもらう。

## 12. 未確認・制約
- 指で引っぱる動きが、実機でうまく指についてくるかは、見本ではマウスでしか確かめていない。
- 「ヒントが出たら まちがい」で、レベルが上がりにくすぎないかは、遊んでもらってから調整する（6秒や、レベルの上がり下がりの数）。
- 英語（べんきょう）は、このあと別の設計書にする。べんきょうのホームの2ページ化は、そのときに行う。
