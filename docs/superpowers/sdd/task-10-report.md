## 実装のポイント（Review Focus との対応）
1. **音声なし**：`voice.isAvailable()===false` のとき画面に `no-voice` クラスを付け、問題文「「あ」は どれかな？」を 52px・枠付きで大きく表示。もういちど きくボタン（スピーカー）は出さない。`speak` はすべて try/catch で包み、結果を待たずに進む。
3. **なぞり**：`pointerdown` で最初の `pointerId` を固定し、指が離れるまで他の指を無視。`touch-action:none`。`resize`／`orientationchange` で Canvas を作り直し、なぞりを消す（150ms のまとめ処理つき）。
4. **利用時間**：`timer.isOver` は**次の問題を出す直前**（`nextQuestion`）でだけ確認。問題の途中では出さない。`timer.start` 時点で既に超過でも、「あそぶ」→`nextQuestion` の isOver で必ずお休み画面になる（onOver には頼らない）。
5. **連打**：選択肢は、正解後 `q.done`、不正解後 700ms の `q.busy` で無視。「できた！」は `judging`、「つぎへ」「あそぶ」は disabled、ログは `q.logged` で1問1回。さらに画面ごとの番号（token）で、前の画面のボタンやタイマーを無視。

その他：
- 最初のタップ（`pointerup`/`touchend`/`keydown`、捕捉フェーズ）で `sfx.play('tap')` と（BGM ONなら）`sfx.startBgm()` → AudioContext 開始。
- BGM の ON/OFF ボタン（音符アイコン、OFFは斜線）を上の帯に配置。設定は `storage.setSettings({bgmOn})` に保存。画面が隠れたら BGM を止め、戻ったら再開。おやすみ画面では止める。
- **ログ**：1問ごとに1回、`area:'hiragana'`, `itemId`＝その文字、`level`＝出題時のレベル。`correct` は「えらぶところで1回目に当たったか」。なぞりの不合格は記録上の不正解にしない（5歳児向けに、なぞりは練習扱い）。
- **レベル**：`adaptive.nextLevel(直近, level, 3)`。レベルが変わったら直近の記録を空にする（連続で上がり過ぎないため）。起動時は記録から、最後のレベルと、そのレベルが続いた分を直近として復元（最後の1問でレベルが変わっていた場合も再現）。
- **出題**：`pickWeighted(候補, 間違い回数, Math.random)`。直前と同じ文字は避ける。選択肢は同じレベルの文字から。
- **なぞり判定**：お手本は `rasterizeGlyph` と同じ字形（`bold 0.8×size sans-serif`）で薄く描く。判定は 160×160 マスク、線の太さはキャンバスの 11%。
- 園児の画面の文字はひらがなと絵だけ（おやすみの「z」もSVGの線で描いた）。おとなゲートと親画面は大人向けなので例外。

## 懸念
1. **テストを開くと、アプリの記録が消える**：`tests/index.html` は同じ `localhost:8080` で `storage.resetAll()` を呼ぶ。`resetAll` は `_forceMemory(true)` でも localStorage の `chiid.*` と IndexedDB を消すため、確認中に作ったプロフィールが実際に消えた。実機配布では関係ないが、確認・QA時は「テストを開くと記録が消える」点に注意が必要。直すなら storage.js の `resetAll` を、強制メモリ時は端末の保存を触らないようにする（Task 2 の範囲なので未変更）。
2. 選択肢カードに、絵と一緒にことば（例「おに」、頭の文字を色付き）を出している。文字の形合わせでも正解できるため、「音を聞いて選ぶ」練習としては易しめ。教育設計の判断が要る。
3. ルート `index.html` はアプリ選択の入口だが、ちいくアプリ内から入口へ戻るボタンは置いていない（子どもが迷わないため）。
4. 親画面でリセットした直後に `timer.stop()` が呼ばれると、消えたプロフィールの利用秒数が端数ぶん再保存されることがある（害は小さい）。
5. `tools/serve.pl` を1行変更した（確認用ツールのみ。アプリには含まれない）。
